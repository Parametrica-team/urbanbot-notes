# Нормативная RAG-база

Локальная система: **нормативный источник → целые пункты с условиями → SQLite FTS + векторы BGE-M3 → выбор оснований Qwen → механическая проверка цитат → интерфейс**.

## Честные границы покрытия

Сохранён официальный снимок раздела 8 СП 4.13130.2013 из DOCX МЧС, учитывающего изменение № 3. После просмотра текста изменения № 4 в открытой публикации и сопоставления с консолидированным текстом **19 совпавших пунктов** включены в обычный режим. В пяти пунктах, включая численно различающийся 8.2.6, найдены расхождения: они исключены из актуальных ответов. Полный официальный текст актуальной редакции в целом не объявляется проверенным. Исходный снимок доступен отдельным явным режимом.

Добавлены ограниченные выдержки из открытых копий: СП 113 — 5 пунктов; СП 42.2026 — 7, включая таблицы 8.16–8.17; СП 476 — 5; СП 396 — 5; СП 59 — 4; СП 551 — 4; СанПиН 2.1.3684-21 — 4; СанПиН 1.2.3685-21 — только пункт 165 о способе расчёта инсоляции. Нормативы продолжительности инсоляции и шумовые таблицы ещё не проверены. Происхождение копии и ограничения показаны в ответе. Официальные сведения о редакциях СП сверены отдельно; это не сверка полного официального текста.

Всего 54 текущих пункта и 24 пункта исторического снимка СП 4. Остальные разделы этих документов и очередь их полной проверки не получают подтверждения автоматически. Существующие карточки Obsidian — навигация. Их `publish: true` не означает нормативную верификацию.

Это извлекающий RAG: модель выбирает идентификаторы оснований, а сервер извлекает и показывает целые дословные пункты с областью применения. Выдуманные идентификаторы и свободные числовые пересказы не принимаются. Совпадение цитаты не доказывает применимость к проекту; релевантность оценивается контрольными вопросами и человеком.

Опубликованные заметки Obsidian входят в отдельный слой `working-note`, поиск по которому пользователь включает явно. Они не получают статус проверенных нормативов. Изменения заметок учитываются после импорта и пересборки; удалённые фрагменты исчезают из нового индекса.

## Запуск на Windows

Требуется Python 3.11+ со стандартной SQLite FTS5, место под runtime и модели (около 10 ГБ с распаковкой), доступ к GitHub и реестру моделей. Библиотеки Python не устанавливаются. Для установки используется официальный portable Ollama 0.40.13 с проверкой SHA-256, без системного сервиса и изменения PATH.

```powershell
./rag/install.ps1
./rag/start.ps1 -PullModels
```

Открыть http://127.0.0.1:48870. Модели доступны только на loopback:11435. Порты 3000, 3001 и 35136 не используются.

Повторный запуск: `./rag/start.ps1`. Остановка собственных процессов: `./rag/stop.ps1`. Скрипт не завершает чужие процессы. Автозапуск при входе в Windows не настроен.

Бинарники, модели и лог Ollama: `%USERPROFILE%/.local/share/urbanbot-rag/`. Индекс, PID и отчёты: `rag/.state/` (игнорируются Git). Исходники документов и реестр сохраняются в репозитории. Не помещать сюда закрытые документы без отдельного решения о доступе: репозиторий публичный.

## Обновление

```powershell
./rag/update.ps1
# Дополнительно обновить публикационные копии заметок:
./rag/update.ps1 -Vault 'C:\path\to\vault'
```

Команда проверяет тесты, строит кандидат индекса, выполняет на нём реальные контрольные вопросы и **только после успешной оценки** атомарно заменяет прежний индекс. При сбое построения или оценки прежний индекс остаётся активным. Сохраняется резервная копия. Неизменённые векторы переиспользуются, изменённые тексты индексируются заново.

Правки Markdown в Obsidian не изменяют нормативный корпус автоматически: сначала нужен проверенный источник и запись в `registry.json`. Источник с новым хешем не получает подтверждение автоматически. Смена модели эмбеддингов требует пересборки.

На проверенной машине текущий CUDA runtime не совместился с установленным драйвером GTX 1070. По умолчанию используется CPU (`RAG_GPU_LAYERS=0`), без изменения драйверов. Ответы могут занимать десятки секунд и более. GPU-режим следует включать только после отдельной проверки совместимости.

Добавление нового документа: сохранить разрешённый к распространению исходник → получить структурированный текст с проверенными таблицами → проверить редакцию/изменения и область применения → заполнить метаданные и SHA-256 → добавить контрольные вопросы → выполнить update. Архив и неподтверждённые материалы исключены по умолчанию.

## Проверки

```powershell
python -m unittest discover -s rag/tests -v
python rag/evaluate.py
python rag/app.py ask --snapshots --question 'Какова ширина пожарного проезда для жилого дома высотой 30 м?'
```

`evaluate.py` использует реальные модели; отчёт в `.state/evaluation.json`. Юнит-тесты используют контролируемые векторы и отдельно проверяют логику. Логи ошибок не подменяются пустыми ответами.

Принятый локальный прогон от 30.10.2026: 31 unit-тест, 14 положительных контрольных вопросов по девяти документам и проверки отказов. [Отчёт с хешами, версиями моделей и выбранными пунктами](verification-2026-10-30.json). Это проверка перечисленных сценариев, а не доказательство полноты всех нормативов.

## Удалённый доступ

GitHub Pages размещает библиотеку, но не Python/Ollama. Локальный интерфейс доступен на этом компьютере, пока работают процессы. Ключи облачных API не нужны; оплачиваются только собственные ресурсы компьютера.

Решение пользователя от 30.10.2026: оставить чат локальным. Развёртывание командного сервера исключено из текущего этапа.

Для командного режима нужны отдельный сервер, HTTPS, авторизация и политика доступа к корпусу. Текущий сервер намеренно привязан к 127.0.0.1 и не предназначен для открытия через проброс порта. Интернет-доступ и круглосуточная работа **не настроены**. Не создавать публичный туннель к локальной машине как замену авторизации.

## Резервная копия

Хранить Git-репозиторий с проверенными исходниками, реестром и тестами, а закрытый Obsidian vault резервировать отдельно. Индекс восстановим пересборкой; для точного воспроизведения дополнительно сохранять версии и digest моделей из `/api/tags`, отчёт оценки и версию runtime. Удаление публичного источника новым коммитом не стирает историю Git.
